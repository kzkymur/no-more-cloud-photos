# iPhone 版 受け入れ確認（TestFlight）

TestFlight で入れた「NMCP Photos」が実機で正しく動くかを確認する手順です。所要時間は 30〜60 分ほどです。
各項目の **確認** にある結果にならなかった場合は、アプリ画面の「前回のエラー」「失敗一覧」の文言とスクリーンショットを開発側に送ってください。

## 準備
- `ios-testflight-setup.md` の手順 8 まで終わっていること（Tailscale に接続済み、サーバ URL を設定済み、フルアクセスを許可済み）。
- Mac の「ターミナル」でサーバの API を見られること（Tailscale 接続済みの Mac で `curl https://<サーバ>/readyz` が通る）。
- 以下では `S=https://<サーバ URL>` と置きます（例: `S=https://photos.example.ts.net`）。

サーバに届いた原本は次のように確認できます。

```sh
# 最近アップロードされたメディアの一覧（id とファイル名）
curl -s "$S/media?profile=standard&limit=20" | python3 -m json.tool | grep -E '"id"|"original_filename"'
# 1 件の原本情報（sha256・サイズ・ダウンロード URL）
curl -s "$S/media/<id>/original" | python3 -m json.tool
```

## 1. 原本がそのまま届く（sha256 と GPS）
1. iPhone の標準カメラで、位置情報をオンにして写真を 1 枚撮ります（HEIC のままで構いません）。
2. アプリを開き、「送信済」が 1 増えるのを待ちます。
3. Mac の「写真」アプリで同じ写真を選び、「ファイル」→「書き出す」→「**未編集のオリジナルを書き出す**」で書き出します。iCloud 写真を使っていない場合は、AirDrop の「オプション」で「すべての写真データ」をオンにして送ります。
4. Mac で sha256 を計算し、サーバ側の値と比べます。

   ```sh
   shasum -a 256 ~/Desktop/IMG_xxxx.HEIC
   curl -s "$S/media/<id>/original" | python3 -m json.tool | grep sha256
   ```

5. サーバの原本をダウンロードして、GPS が残っているか確認します（`brew install exiftool` が必要です）。

   ```sh
   curl -s "$(curl -s "$S/media/<id>/original" | python3 -c 'import json,sys;print(json.load(sys.stdin)["file_url"])')" -o /tmp/orig
   exiftool -GPSPosition /tmp/orig
   ```

**確認**: 2 つの sha256 が一致すること。GPSPosition が表示されること。

## 2. Live Photo は静止画と動画の両方が届く
1. Live Photo をオンにして 1 枚撮ります。
2. 「送信済」が **2** 増えることを確認します（静止画の HEIC と動画の MOV）。
3. 手順 1 の一覧に、同じ名前の `.HEIC` と `.MOV` があることを確認します。

**確認**: 両方が届いていること。サーバ上でのペア表示は今後の対応（issue #74）なので、別々のメディアとして見えていれば正常です。

## 3. iCloud にだけある写真も届く（iCloud 写真を使っている場合）
1. 「設定」→「写真」で「**iPhone のストレージを最適化**」になっていることを確認します。
2. 古い写真（端末に原本が無く、iCloud にだけあるもの）が含まれている状態で、「今すぐ同期」を押します。
3. Wi-Fi に接続したまましばらく待ちます。iCloud からのダウンロードが入るので、通常より時間がかかります。

**確認**: 「未送信」が減っていくこと。iCloud から取得できなかった写真は「失敗一覧」に理由とともに表示され、ほかの写真の送信は止まらずに続くこと。

## 4. 画面ロック中・バックグラウンドでも送られる
1. 写真を 10 枚ほど撮ります（1 本 1 分程度の動画を含めると確認しやすくなります）。
2. アプリを開いて送信が始まったら、ホーム画面に戻り、画面をロックして 10〜15 分置きます（Wi-Fi に接続、できれば充電中）。
3. アプリを開きます。

**確認**: ロックしている間にも「送信済」が増えていること。iOS はバックグラウンドで送る量を制限するので、全部は終わっていなくても構いません。アプリを開くと残りが送信されること。

## 5. 強制終了しても回復する
1. 大きめの動画（数百 MB）を送信している最中に、アプリスイッチャーでアプリを上にスワイプして終了させます。
2. もう一度アプリを開きます。

**確認**: その動画が「失敗」のまま止まらず、再び送信されて「送信済」になること。サーバ側で同じ動画が二重に登録されていないこと（手順 1 の一覧で同じファイル名が 1 件だけであること）。

## 6. 「選択した写真のみ」許可のとき
1. 「設定」→「プライバシーとセキュリティ」→「写真」→「NMCP Photos」で「**制限付きアクセス**」にし、写真を 2〜3 枚だけ選びます。
2. アプリを開きます。

**確認**: 「一部の写真のみアクセスが許可されています」という警告が表示されること。選んだ写真だけが対象になること。すでに送信済みの件数が減らないこと。

3. 確認が終わったら、警告の「すべて許可する」から、または「設定」で「**フルアクセス**」に戻します。

**確認**: 「合計」が元に戻り、残りの写真が送信されること。

## 結果の送り方
各項目に OK / NG を付け、NG の項目には次を添えて開発側に送ってください。
- アプリの画面のスクリーンショット
- 「前回のエラー」と「失敗一覧」の文言
- だいたいの時刻
