# Requirements traceability

This matrix covers the published Core architecture and Worker design requirements, including system boundaries, and maps implementation issues #3-#21 to required evidence. Contract sections are normative; issue numbers identify implementation ownership. "Integration" means real PostgreSQL/files/tooling where relevant, not a mock-only test. Each feature issue owns its unit and local integration evidence only; full-process scenarios, cross-feature fault injection, and release evidence stay in the dedicated #21 issue and PR. #20 owns local Nginx/service/Range checks. Operational checks that require the deployment host remain explicit rather than being reported as passed in CI.

Contract links: [HTTP API and CLI](contracts/core-api.md), [state, storage, workers, and operations](contracts/state-and-storage.md).
